# 04_content_scope.md

# Content Scope

## Objetivo

Este documento establece los límites máximos del contenido del proyecto.

Su propósito es proteger el alcance del experimento.

Toda nueva idea deberá adaptarse a estos límites o quedar pospuesta para una posible versión futura.

---

# Filosofía

Este proyecto no pretende crear un mundo enorme.

Pretende demostrar que un pequeño conjunto de sistemas sencillos puede construir una experiencia narrativa completa.

El contenido deberá favorecer:

- variedad;
- rejugabilidad;
- coherencia temática;

antes que cantidad.

---

# Cartas

## Cantidad objetivo

**30–40 cartas.**

Este límite incluye todo el contenido jugable.

No se crearán expansiones de contenido durante el desarrollo inicial.

---

## Tipos de carta

Las cartas podrán representar:

- situaciones narrativas;
- amenazas;
- posibles aliados;
- hallazgos;
- anomalías;
- finales parciales.

Todas utilizan exactamente el mismo sistema de resolución.

No existen reglas específicas para cada categoría.

---

## Estructura

Cada carta puede contener:

- ilustración;
- texto;
- una o varias decisiones;
- una amenaza opcional;
- consecuencias;
- cambios persistentes.

No todas las cartas deben utilizar todos los elementos.

---

# Aliados

## Cantidad

Máximo recomendado:

**5 aliados.**

Cada aliado debe poseer:

- identidad visual;
- pequeña descripción narrativa;
- dado propio;
- especialización sencilla.

El jugador nunca podrá controlar más de un aliado simultáneamente.

---

# Objetos

## Cantidad

Entre **10 y 12 objetos**.

El catálogo deberá permanecer estable durante toda la producción.

---

## Filosofía

Los objetos deben:

- comprenderse inmediatamente;
- tener una única función principal;
- evitar excepciones.

No existirán:

- categorías;
- rarezas;
- fabricación;
- mejoras;
- comercio;
- economía.

---

# Ilustraciones

Cada carta dispondrá de una ilustración principal.

Dirección artística:

- inspiración en grabados clásicos;
- predominio del blanco y negro;
- incorporación gradual del color como recurso narrativo.

No se producirán variantes múltiples de una misma ilustración salvo necesidad evidente.

---

# Música

El proyecto utilizará un conjunto reducido de ambientes reutilizables.

No existirá una pista exclusiva para cada carta.

Categorías iniciales:

- despertar;
- vacío;
- contemplación;
- amenaza;
- presencia;
- recuerdo;
- desenlace.

El silencio forma parte de la dirección sonora.

---

# Voz

La narración mediante voz será opcional.

Solo determinadas cartas podrán incluir una frase hablada.

No se narrará el juego completo.

---

# Interfaz

La interfaz permanecerá deliberadamente minimalista.

Elementos visibles:

- carta;
- ilustración;
- texto;
- decisiones;
- dados;
- inventario reducido;
- shader de fondo.

No existirán:

- ventanas complejas;
- barras permanentes;
- minimapas;
- paneles secundarios.

---

# Shader de fondo

El shader representa el estado emocional del sueño.

No constituye un sistema jugable independiente.

Los cambios de shader acompañan la evolución narrativa.

Ejemplos:

- vacío;
- inquietud;
- amenaza;
- recuerdo;
- presencia.

---

# Persistencia

El juego conserva únicamente:

- estado del protagonista;
- estado del aliado;
- inventario;
- variables narrativas;
- estado del sueño.

No se implementarán sistemas persistentes adicionales.

---

# Duración objetivo

Una partida completa deberá poder finalizarse aproximadamente entre:

**30 y 60 minutos.**

El objetivo es favorecer la rejugabilidad antes que la duración.

---

# Producción

El contenido deberá mantenerse compatible con el calendario definido en `01_scope.md`.

Todo elemento nuevo deberá responder afirmativamente a las siguientes preguntas:

- ¿Aporta valor directo al juego?
- ¿Puede implementarse dentro del tiempo previsto?
- ¿No introduce un sistema nuevo?
- ¿Respeta la dirección artística?
- ¿Puede reutilizar el Narrative Core existente?

Si alguna respuesta es negativa, la idea deberá posponerse.

---

# Elementos explícitamente fuera del alcance

No forman parte del proyecto inicial:

- mapas;
- exploración espacial;
- raycaster;
- editor;
- IA de enemigos;
- árboles de diálogo complejos;
- combate táctico;
- niveles;
- experiencia;
- habilidades;
- clases;
- progresión extensa;
- crafting;
- comercio;
- economía;
- equipamiento complejo;
- múltiples compañeros;
- misiones secundarias;
- coleccionables;
- logros;
- contenido descargable.

---

# Regla de congelación

Una vez iniciada la producción, el contenido definido en este documento se considera congelado.

Las nuevas ideas se documentarán para futuros experimentos o una posible versión posterior, pero no modificarán el alcance del proyecto actual.

---

# Definición de éxito

El proyecto se considerará completado cuando disponga de:

- una experiencia jugable completa;
- un principio;
- un final;
- 30–40 cartas;
- una dirección artística coherente;
- una banda sonora funcional;
- un sistema de reglas estable;
- una publicación pública.

No será necesario ampliar el contenido para considerar el experimento un éxito.

---

# Principio final

> **Es preferible publicar un juego pequeño, coherente y terminado que un proyecto más ambicioso que nunca llegue a completarse.**
